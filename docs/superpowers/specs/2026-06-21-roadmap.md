# Feuille de route cdp-scraper — vers une version publiable

> Établie le 2026-06-21. Découpe le backlog d'améliorations en versions
> successives, chacune traitée comme un sous-projet avec son propre cycle
> *spec → plan → implémentation → revue*.

## Principe

Le projet (scraper + viewer) est fonctionnellement abouti. Avant publication
et promotion, on enchaîne des versions cohérentes plutôt qu'un seul gros lot.
L'ordre privilégie d'abord le filet de sécurité (qualité/CI), puis le vrai
manque fonctionnel (synchronisation), puis le confort, puis la diffusion.

# Spec — v1.1 « Fondations qualité »

> Date : 2026-06-21. Premier sous-projet de la [feuille de route](2026-06-21-roadmap.md).
> Objectif : poser le filet de sécurité (versioning, CI, tests) et nettoyer le
> dépôt avant d'ajouter des fonctionnalités, en vue de la publication.

## Contexte

`cdp-scraper` (scraper + viewer) est fonctionnellement abouti. Avant publication,
cette version durcit le projet sans introduire de nouvelle fonctionnalité
utilisateur (hormis `--version` pour le viewer). Trois décisions de cadrage ont
été prises :

1. **S6** : retirer le script `telechargeur_batch.py` (référencé mais absent) et
   les options orphelines `--liste` / `--cookie-sortie`.
2. **Python** : déclarer officiellement **3.10+** (le viewer plante à l'import
   sur 3.8/3.9 à cause d'annotations `X | None` / `list[str]` évaluées à la
   définition ; 3.8 et 3.9 sont en fin de vie).
3. **Versioning** : une **version unique de projet** (SemVer), démarrage
   **1.1.0**, chaque script gardant son `__version__`, bumpés ensemble.

## Périmètre

Quatre volets : S6 (nettoyage), alignement Python 3.10+, P4 (versioning +
CHANGELOG), P3 + Q1 (CI + tests de robustesse).

### 1. S6 — Retrait de `telechargeur_batch.py`

Dans `cdp_scraper.py` :
- Supprimer la fonction `sauvegarder_cookies()`.
- Supprimer l'option CLI `--cookie-sortie` et son bloc de traitement
  (appel à `sauvegarder_cookies`).
- Supprimer l'option CLI `--liste` et son bloc d'export d'URLs (y compris
  l'`sys.exit(0)` associé et l'astuce affichée).
- Retirer toute mention de `telechargeur_batch.py` : docstring d'en-tête,
  `epilog` de `parse_args`, commentaires.
- Retirer le commentaire périmé au-dessus de `DEPOT`
  (« Remplacez par l'URL réelle après publication ») — l'URL est déjà correcte.

**Critères d'acceptation :**
- `python cdp_scraper.py --help` ne mentionne ni `--liste`, ni `--cookie-sortie`,
  ni `telechargeur_batch`.
- `grep -ri "telechargeur_batch\|cookie-sortie\|--liste" .` ne renvoie rien
  (hors ce spec et le CHANGELOG historique).
- La suite de tests reste verte.

### 2. Alignement Python 3.10+

- `README.md` : remplacer « Python ≥ 3.8 » par « Python ≥ 3.10 ».
- `docs/cdp_scraper_doc.md` : aligner toute mention de version.
- Pas de `pyproject.toml`/packaging dans cette version (prévu en v2.0 avec le
  `.exe`). Le README est la source de vérité de la version requise.

**Critères d'acceptation :**
- Aucune mention résiduelle de « 3.8 » comme version minimale dans la doc.

### 3. P4 — Versioning unifié + CHANGELOG

- `cdp_scraper.py` : `__version__` passe de `"1.0.0"` à `"1.1.0"`.
- `cdp_viewer.py` : ajouter `__version__ = "1.1.0"`.
- `cdp_viewer.py` : ajouter l'option `--version` à l'`ArgumentParser`
  (`action="version"`, `version=f"cdp-viewer {__version__}"`).
- Créer `CHANGELOG.md` au format *Keep a Changelog* (en français) :
  - `[1.1.0] - 2026-06-21` : section « Supprimé » (options batch), « Modifié »
    (Python 3.10+ requis), « Ajouté » (CI, `--version` du viewer, tests de
    parsing), « Versioning » (version unique de projet).
  - `[1.0.0]` : entrée de référence (état publié initial : scraper + viewer).

**Critères d'acceptation :**
- `python cdp_scraper.py --version` affiche `cdp-scraper 1.1.0`.
- `python cdp_viewer.py --version` affiche `cdp-viewer 1.1.0`.
- `CHANGELOG.md` existe et liste les changements de la 1.1.0.

### 4. P3 — CI GitHub Actions + Q1 — Tests de robustesse

**CI** — `.github/workflows/ci.yml` :
- Déclencheurs : `push` et `pull_request`.
- Jobs :
  - Ubuntu × Python `3.10`, `3.11`, `3.12`, `3.13`.
  - Windows (`windows-latest`) × Python `3.12` (couvre les chemins spécifiques
    Windows testés en `skipUnless`).
- Étapes : `checkout` → `actions/setup-python` → `pip install -r requirements.txt`
  → `python -m unittest discover -s tests`.

**Q1 — Tests de parsing** (dans `tests/test_cdp_scraper.py`, avec
`tests/fixtures/` pour les pages HTML longues) :
- `analyser_page` :
  - le bloc « Documents récents » (nom contenant `/`) est ignoré ;
  - mélange dossiers + documents sur une même page ;
  - document sans `docdonnees` → `type` vide, URL toujours en `&dl` ;
  - entités HTML dans les noms (`&amp;`, accents) correctement déséchappées.
- `crawler_progcolles` / `_html_progcolles` :
  - mode « PDF par semaine » : `RE_PC_LIEN` extrait les liens, suffixe `(pdf)`
    retiré, chemin `<matiere>/Programme de colles` ;
  - mode « texte » : page nettoyée → HTML autonome sans `<script>`,
    `recherchecolle`, ni bloc `icones` ;
  - contenu protégé (« Ce contenu est protégé ») → ignoré.
  - Réalisé via un faux objet `session` renvoyant des pages figées (pas de réseau).
- Utilitaires :
  - `nom_sur` : caractères interdits remplacés, troncature à 200, fallback.
  - `nom_fichier` : `Content-Disposition` prioritaire ; sinon nom + extension
    déduite du type.
  - `_cle_rep` : déduplication (retrait des paramètres `ordre`/`v`).

**Critères d'acceptation :**
- Le workflow CI est présent et passe sur toute la matrice.
- Les nouveaux tests passent et couvrent les cas ci-dessus.
- `__version__` de `cdp_scraper` et `cdp_viewer` sont égaux (test garde-fou).

## Hors périmètre

- Toute fonctionnalité des versions ultérieures (synchro, viewer enrichi,
  packaging `.exe`, etc.) — voir la feuille de route.
- Packaging (`pyproject.toml`, distribution) : reporté en v2.0.

## Risques / points d'attention

- L'import de `cdp_scraper` exécute du code au niveau module
  (`_assurer_dependances`) : la CI doit installer `requests` avant les tests.
- La suite `tests/test_cdp_viewer.py::TestServeur` lie un port éphémère sur
  `127.0.0.1` : compatible CI.
- Les tests `win32` (`skipUnless`) ne s'exécutent que sur le job Windows.

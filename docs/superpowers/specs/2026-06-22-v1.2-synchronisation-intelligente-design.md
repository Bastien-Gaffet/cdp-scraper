# v1.2 « Synchronisation intelligente » — Design

> Spec établie le 2026-06-22. Sous-projet de la [feuille de route](2026-06-21-roadmap.md).
> Cycle : *spec → plan → implémentation → revue*. Couvre **S2** (manifeste JSON),
> **S1** (synchro incrémentale), **S4** (reprise des échecs), **V1** (dates +
> « récemment ajoutés » dans le viewer).

## 1. Objectif

Permettre de garder ses cours à jour toute l'année : au lieu de re-télécharger
aveuglément (ou de simplement sauter ce qui existe déjà, sans jamais détecter
les mises à jour), le scraper ne récupère **que ce qui est nouveau ou a changé**
côté serveur, retente proprement les échecs, et le viewer met en avant les
ajouts récents.

Le gain fonctionnel par rapport à v1.1 : aujourd'hui un document **mis à jour**
sur cahier-de-prepa n'est **jamais** re-téléchargé (le code saute tout fichier
déjà présent). v1.2 corrige ce manque.

## 2. Principe de détection des changements (approche retenue)

La page de listing affiche déjà, à côté de chaque document, une chaîne
`docdonnees` au format `(type, date, taille)` — ex. `(pdf, 1 jan, 100 ko)` —
**récupérée gratuitement pendant le crawl actuel**. Le code actuel n'en garde
que le type (`split(",")[0]`).

**Détection = comparaison de cette chaîne brute par id.** Si la chaîne
`docdonnees` d'un id diffère de celle mémorisée → le document a changé → on le
re-télécharge. Aucune requête HTTP supplémentaire (respecte l'engagement « un
seul flux mesuré » des conditions d'usage). On stocke aussi la **taille réelle**
du fichier téléchargé comme recoupement, et un drapeau `--complet` force une
resynchro intégrale en cas de doute.

Alternatives écartées :
- **Sondage HEAD / If-Modified-Since / ETag** : une requête de plus par document
  même quand rien ne change (alourdit le serveur de l'association) ; `download.php`
  (PHP) ignore souvent HEAD et les en-têtes conditionnels → peu fiable.
- **Hash de contenu (re-télécharger puis comparer)** : aucune économie de bande
  passante, annule l'intérêt de la synchro incrémentale.

> Note : on ne cherche pas à parser finement la date affichée par le site (fuzzy,
> dépendante de la locale). Pour **détecter** un changement, comparer la chaîne
> suffit. Pour **dater** un ajout dans le viewer, on utilise les horodatages
> absolus du scraper (voir §3 `premiere_vue`/`derniere_maj`).

## 3. S2 — Manifeste JSON (fondation)

### Module partagé `cdp_manifeste.py`

Le scraper *écrit* le manifeste, le viewer le *lit*. Pour éviter de dupliquer la
connaissance du schéma, toute la logique vit dans un nouveau module importé par
les deux scripts. Frontière nette, testable isolément.

API exposée :

- `charger(dossier_classe: Path) -> dict` — lit `.cdp-manifest.json`, renvoie un
  manifeste vide si absent.
- `enregistrer(dossier_classe: Path, manifeste: dict) -> None` — écriture atomique
  (fichier temporaire + renommage).
- `empreinte(doc: dict) -> str` — chaîne `docdonnees` brute ; pour un contenu
  généré (programme de colles texte, sans `docdonnees`), un hash court du HTML.
- `planifier(crawl: list[dict], manifeste: dict) -> dict` — fonction **pure** de
  catégorisation (voir §4).

### Emplacement

Un manifeste **par classe** : `cours_cdp/<classe>/.cdp-manifest.json`, co-localisé
avec les données qu'il décrit (déplacer le dossier emporte le manifeste). Le point
initial le masque ; le viewer **ignore désormais les noms commençant par `.`**
(amélioration de `lister_classes` et `_noeud`).

### Schéma (`version: 1`)

```json
{
  "version": 1,
  "classe": "pcsi2-descartes",
  "url": "https://cahier-de-prepa.fr/pcsi2-descartes",
  "derniere_synchro": "2026-06-22T14:30:00",
  "documents": {
    "1234": {
      "url": "https://cahier-de-prepa.fr/.../download?id=1234&dl",
      "nom": "TP07.pdf",
      "chemin": "Physique/TP",
      "type": "pdf",
      "empreinte": "pdf, 1 jan, 100 ko",
      "taille": 102400,
      "statut": "ok",
      "premiere_vue": "2026-06-22T14:30:00",
      "derniere_maj": "2026-06-22T14:30:00",
      "erreur": null
    }
  }
}
```

| Champ | Rôle |
|---|---|
| clé (`"1234"`) | id cahier-de-prepa (`download?id=N`) ; clé de comparaison |
| `url` | URL de téléchargement directe ; permet la reprise sans re-crawl (S4) |
| `nom` | nom **réel** sur le disque (après téléchargement / Content-Disposition) |
| `chemin` | dossier relatif dans la classe ; `<chemin>/<nom>` localise le fichier |
| `type` | type extrait du listing (comme aujourd'hui) |
| `empreinte` | chaîne `docdonnees` brute = signal de changement |
| `taille` | taille réelle téléchargée (recoupement) |
| `statut` | `ok` \| `echec` \| `disparu` |
| `premiere_vue` | date d'ajout absolue (horodatage scraper) → viewer V1 |
| `derniere_maj` | date du dernier (re)téléchargement |
| `erreur` | dernier message d'erreur si `statut=echec`, sinon `null` |

Cas particuliers :
- **Programme de colles texte** : id `pc_<cle>`, pas d'`url`, contenu généré
  localement → `empreinte` = hash court du HTML généré.
- **Document sans `docdonnees`** : `empreinte` vide → repli sur le comportement
  actuel (ne pas re-télécharger si le fichier est présent).

## 4. S1 — Synchro incrémentale

### Planification explicite

La décision « télécharger ou non » remonte du `telecharger` actuel vers une étape
de planification dédiée. `planifier(crawl, manifeste)` range chaque document
(comparaison sur l'**id**) :

| Situation | Catégorie | Action |
|---|---|---|
| id absent du manifeste | `nouveau` | télécharger |
| id présent, empreinte **identique**, fichier présent, `statut=ok` | `a_jour` | ignorer |
| id présent, empreinte **différente** | `modifie` | re-télécharger (écrase) |
| id présent mais `statut=echec` ou fichier absent | `a_reprendre` | re-télécharger |
| empreinte vide (pas de `docdonnees`) | `a_jour` si fichier présent, sinon `nouveau` | repli conservateur |
| id du manifeste **absent du crawl** | `disparu` | conserver le fichier, `statut=disparu`, ne rien supprimer |

### Modifications du scraper

- **`analyser_page`** conserve la chaîne `docdonnees` complète (`empreinte`) en
  plus du type déjà extrait.
- Le `main()` charge le manifeste, crawle, appelle `planifier`, ne télécharge que
  les catégories `nouveau` / `modifie` / `a_reprendre`, puis ré-enregistre le
  manifeste.
- Après chaque téléchargement, l'entrée du manifeste est mise à jour (`statut`,
  `taille`, `empreinte`, `derniere_maj`, et `premiere_vue` si nouveau).

### Drapeau `--complet`

Ignore la comparaison d'empreinte et re-télécharge tout (met quand même le
manifeste à jour). Filet de sécurité si une modif a pu être ratée.

### Robustesse — écriture atomique des téléchargements

Bug actuel : `telecharger` écrit directement dans le fichier cible ; une coupure
en plein flux (Ctrl-C, réseau) laisse un fichier tronqué de taille > 0, considéré
« déjà présent » au run suivant → jamais réparé. Correction : téléchargement dans
un fichier temporaire (`.part`) puis **renommage atomique** après succès. Une
interruption ne laisse jamais de fichier corrompu validé.

## 5. S4 — Reprise des échecs

Deux usages complémentaires :

1. **Reprise automatique au run normal** — déjà couverte par la catégorie
   `a_reprendre` (§4) : un run normal re-crawle et retélécharge ce qui est en
   `echec` ou manquant. Aucun code supplémentaire.
2. **Mode rapide `--reprise`** — relit le manifeste et retente **uniquement** les
   entrées `echec`/fichier manquant, **sans crawler** (on saute l'exploration, la
   partie lente). Déroulé :
   - Connexion, puis **pas de crawl**.
   - Lecture des entrées à reprendre depuis le manifeste (chacune a `url`,
     `chemin`, `type`) → appel direct de `telecharger`.
   - Mise à jour du manifeste.
   - Manifeste absent → message « rien à reprendre, lancez d'abord une synchro
     normale », sortie propre.

**Portée de `--reprise`** : uniquement les documents ayant une `url` (vrais
téléchargements). Les programmes de colles texte (contenu généré, sans `url`)
sont repris par le run normal ; documenté dans l'aide du drapeau.

**Suivi des échecs** : `telecharger` renvoie déjà `echec` sur
`RequestException`/`OSError`. On enregistre `statut=echec` + message dans
`erreur` et on **conserve l'entrée**. Au succès suivant, `statut` repasse à `ok`
et `erreur` à `null`.

**`--complet` et `--reprise` sont mutuellement exclusifs** → erreur d'usage
claire si les deux sont passés ensemble.

## 6. V1 — Viewer : dates + « récemment ajoutés »

### Source des dates

À la construction de l'arbre d'une classe, le viewer charge le manifeste (via
`cdp_manifeste.charger`) et l'indexe par chemin relatif (`<chemin>/<nom>`). Chaque
nœud *fichier* gagne un champ `date` = `premiere_vue`.

- **Repli gracieux** : fichier absent du manifeste (téléchargements d'avant v1.2,
  ou manifeste manquant) → `mtime` du fichier. Le viewer reste fonctionnel sans
  manifeste.
- `.cdp-manifest.json` et tout nom en `.` sont exclus de l'arbre.

### Affichage

Chaque fichier affiche sa date d'ajout (format court FR, ex. « 22 juin »),
discrètement à côté de la taille existante.

### Vue « récemment ajoutés » (fenêtre glissante)

Une entrée en tête de la classe liste à plat les fichiers dont la date
d'ajout/maj tombe dans les **N derniers jours**, triés du plus récent au plus
ancien, avec un **sélecteur de durée** (7 / 30 / 90 jours). Le filtrage est
**côté client** à partir du champ `date` déjà présent dans l'arbre (pas de
nouvelle route serveur). Chaque résultat reste cliquable (ouvre/révèle le
fichier) comme dans l'arbre. Aucun fichier dans la fenêtre → message « Aucun
ajout dans les N derniers jours ».

### Versioning

Le viewer passe en `1.2.0` (cohérent avec le scraper), conformément au
versioning unifié posé en v1.1.

## 7. CLI & résumé

Nouveaux drapeaux du scraper :

- `--complet` — ignore le manifeste, re-télécharge tout.
- `--reprise` — reprise rapide ciblée des échecs sans crawl.
- Sans drapeau = **synchro incrémentale** (nouveau mode normal, y compris en
  interactif, sans question supplémentaire).

Résumé final enrichi, distinguant : **Nouveaux**, **Mis à jour**,
**À jour (ignorés)**, **Échecs**, **Disparus du serveur (conservés)**, + volume
téléchargé. En mode `--reprise` : « Repris : X / Échecs persistants : Y ».

## 8. Gestion d'erreurs & compatibilité

- **Manifeste corrompu** (JSON invalide) → avertissement non bloquant, on repart
  d'un manifeste vide (dégrade au pire en re-synchro complète, jamais de perte).
- **Manifeste de version future** (`version` > connue) → arrêt propre avec
  message, plutôt qu'une mauvaise interprétation.
- **Écriture du manifeste** atomique (temporaire + renommage).
- **Compat ascendante** : dossier sans manifeste (v1.1) → premier run v1.2 le
  reconstruit ; les fichiers déjà présents ne sont pas re-téléchargés inutilement.

## 9. Tests (hors-ligne, dans la lignée des 56 tests v1.1)

- `planifier()` : chaque catégorie (nouveau, à jour, modifié, à reprendre,
  disparu, empreinte vide) sur manifeste + crawl simulés.
- Manifeste : round-trip charger/enregistrer, JSON corrompu, version future,
  écriture atomique.
- `analyser_page` : l'empreinte `docdonnees` complète est conservée (extension
  des tests existants).
- Reprise : sélection des seules entrées `echec`/manquantes, sans réseau.
- Viewer : indexation manifeste → champ `date`, repli sur `mtime`, exclusion des
  dotfiles, filtre « N derniers jours ».
- Écriture atomique des téléchargements (`.part` → renommage) : simulation
  d'interruption.

## 10. Hors périmètre (YAGNI)

- Suppression des fichiers disparus côté serveur (on conserve : c'est une
  sauvegarde).
- Sondage HEAD / requêtes conditionnelles.
- Favoris / annotations viewer (V5, plus tard).
- Parsing fin de la date affichée par le site.

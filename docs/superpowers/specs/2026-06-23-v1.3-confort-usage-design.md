# Spec — v1.3 « Confort d'usage »

> Établie le 2026-06-23. Sous-projet de la feuille de route
> (`docs/superpowers/specs/2026-06-21-roadmap.md`). Cycle *spec → plan →
> implémentation → revue*. Cible de version : **1.3.0**.

## Périmètre

Quatre améliorations de confort, sans rupture de compatibilité :

- **S3** Multi-classes en un seul run.
- **S5** Config mémorisée (URL / login / dossier — **jamais le mot de passe**).
- **Q2** Pages d'erreur du viewer soignées.
- **V6** Navigation clavier + recherche améliorée dans le viewer.

S3 et S5 sont traités ensemble : la config est une **liste de classes**, et le
multi-classes en découle naturellement (un run traite tout ou un sous-ensemble).

## Principes directeurs

- **Rétrocompatibilité totale.** Avec `--url` (ou sans config), le comportement
  reste celui de v1.2.
- **Sécurité.** Aucun mot de passe n'est jamais écrit sur disque. Le login peut
  l'être (par classe). Cohérent avec la règle projet (cf. mémoire
  `cdp-scraper-github`).
- **Cohérence d'architecture.** Nouveau module partagé `cdp_config.py` calqué
  sur `cdp_manifeste.py` (fonctions pures + I/O atomique, testables hors-ligne).
  Q2 et V6 restent dans `cdp_viewer.py` (fichier unique serveur + frontend).
- **Tests 100 % hors-ligne**, dans la lignée des 95 tests existants.

## 1. S5 — Config mémorisée (`cdp_config.py`)

### Module

Nouveau fichier `cdp_config.py`, importé par `cdp_scraper.py`. API :

- `chemin_config(override: str | None = None) -> Path`
  Résolution **en cascade** :
  1. `override` (flag `--config CHEMIN`) si fourni ;
  2. sinon `./.cdp-scraper/config.json` **s'il existe** (usage script, dossier
     courant) ;
  3. sinon `~/.cdp-scraper/config.json` (HOME — défaut pour la lecture *et*
     l'écriture quand aucun fichier local n'existe ; prêt pour le futur `.exe`).
- `charger(chemin: Path) -> dict`
  Lit le JSON. Absence tolérée → `{"version": 1, "classes": []}`. Une version de
  schéma supérieure lève une erreur claire (`ConfigVersionFuture`, sur le modèle
  de `ManifesteVersionFuture`).
- `enregistrer(chemin: Path, config: dict)`
  Écriture **atomique** (`.part` → renommage), `mkdir(parents=True)` du dossier
  parent au besoin.
- `ajouter_ou_maj(config: dict, classe: dict) -> dict`
  Insère ou met à jour l'entrée dont la clé est `nom` (slug de classe).
- `selectionner(config: dict, noms: list[str]) -> list[dict]`
  Filtre les entrées par `noms`. Lève une erreur explicite si un nom est inconnu
  (en listant les noms disponibles).
- `retirer(config: dict, nom: str) -> dict`
- `lister(config: dict) -> list[dict]`

### Schéma du fichier

```json
{
  "version": 1,
  "classes": [
    {
      "nom": "mpsi",
      "url": "https://cahier-de-prepa.fr/mpsi-machin",
      "login": "prof@exemple.fr",
      "dossier": "cours_cdp"
    }
  ]
}
```

- `nom` : slug dérivé de l'URL, même logique que `nom_classe`
  (`cdp_scraper.py` actuel, dérivation du dernier segment du path).
- **Aucun champ mot de passe**, jamais.
- Identifiants **par classe** : chaque entrée porte son `login`. Le mot de passe
  est demandé par classe au lancement.

## 2. S3 — Multi-classes en un run (`cdp_scraper.py`)

### Nouveaux arguments

| Argument | Rôle |
|----------|------|
| `noms...` (positionnels) | Classes à traiter (slugs présents dans la config). Aucun = tout / menu. |
| `--config CHEMIN` | Force le chemin du fichier de config. |
| `--config-lister` | Affiche les classes mémorisées puis quitte. |
| `--config-supprimer NOM` | Retire une classe de la config puis quitte. |
| `--tout` | Traite toutes les classes de la config sans menu (pour scripts). |

Les arguments existants (`--url`, `--login`, `--mdp`, `--sortie`, `--simulation`,
`--profondeur`, `--delai`, `--sans-colles`, `--complet`, `--reprise`,
`--accepter-conditions`) sont **inchangés**.

### Flux de `main`

1. **Parse args.**
2. **Commandes de gestion** : si `--config-lister` ou `--config-supprimer`,
   exécuter puis `return` immédiat.
3. **Détermination des classes à traiter :**
   - `--url` fourni → **mode mono-classe historique** (aucune config requise,
     comportement v1.2 strict).
   - sinon, charger la config :
     - `noms` en argument → `selectionner(config, noms)` ;
     - aucun `noms`, `--tout` → toutes les classes ;
     - aucun `noms`, config **non vide**, interactif → **menu** listant les
       classes ; saisie type « 1,3 » / « tout » / Entrée = tout ;
     - config **vide** → **mode interactif mono-classe** actuel (demande
       url/login/dossier/…).
4. **Boucle sur les classes retenues.** Pour chacune :
   - bannière `── Classe : <nom> ──` ;
   - mot de passe demandé (repli sur `--mdp` global si fourni) ;
   - pipeline existant **inchangé** : connexion → crawl (+ colles) → planif
     (manifeste) → téléchargement atomique → enregistrement manifeste.
5. **Proposition de mémorisation** : après un run **mono-classe** réussi d'une
   classe **absente** de la config, en mode interactif :
   « Mémoriser cette classe (url/login/dossier) ? [O/n] » →
   `ajouter_ou_maj` + `enregistrer`.
6. **Résumé global** : agrégé par classe + cumul (réutilise le résumé existant
   par classe, ajoute un total quand plusieurs classes).

### Refactor

Le pipeline d'une classe est extrait dans une fonction `traiter_classe(...)`
(connexion → téléchargement → manifeste) afin que la boucle multi-classes reste
lisible et que la logique soit testable. `main` orchestre : config, sélection,
boucle, résumé.

## 3. Q2 — Pages d'erreur soignées (`cdp_viewer.py`)

### Mécanisme

- Nouvelle fonction `page_erreur(code, titre, message) -> bytes` : HTML autonome
  (CSS inline, comme la page principale), reprenant les variables de thème
  (`--bg`, `--fg`, `--muted`, `--accent`) et **respectant le thème clair/sombre**
  via `prefers-color-scheme` (la page d'erreur n'a pas accès au choix manuel
  stocké en `localStorage` ; on suit la préférence système, repli raisonnable).
- `_erreur(code, message)` est réécrit pour servir cette page en
  `text/html; charset=utf-8` (au lieu de `text/plain`). La **signature reste**,
  les sites d'appel existants continuent de fonctionner.
- Mise en page : grand code d'erreur, titre court, message contextuel, lien
  **« Retour à l'accueil »** (`/`). Pas d'emoji (parti pris SVG du viewer).

### Messages contextuels

| Code | Contexte | Titre | Message |
|------|----------|-------|---------|
| 404 | classe | Classe introuvable | « Cette classe n'existe pas ou n'a pas encore été téléchargée. Lancez `cdp_scraper.py` pour la récupérer. » |
| 404 | fichier | Fichier introuvable | « Ce fichier n'existe plus — il a peut-être été supprimé ou renommé depuis la dernière synchronisation. » |
| 403 | — | Accès refusé | « Ce chemin sort du dossier des cours autorisé. » |
| 500 | — | Erreur interne | Message générique + détail technique (`str(e)`) en plus petit. |

Pour distinguer 404 classe vs fichier, on **enrichit les appels** avec une clé de
contexte (ex. `self._erreur(404, "classe")`) plutôt que de deviner d'après le
texte.

### Hors-scope

Le 500 des routes **API** (`/api/...`) reste en **JSON**
(`_envoyer_json(500, {"erreur": ...})`) : c'est consommé par le JS, pas une page.
Seules les routes « navigateur » passent en HTML thémé.

## 4. V6 — Navigation clavier + recherche améliorée (`cdp_viewer.py`)

### Navigation clavier

État JS : index `selection` pointant l'élément actif de la liste affichée (liste
normale, résultats de recherche, ou « récents » — tous rendus via `ligne(...)`).
L'élément sélectionné porte une classe CSS `.actif` (fond `--accent` atténué) et
est ramené dans la vue (`scrollIntoView`).

Gestionnaire global `keydown` sur `document` :

| Touche | Action |
|--------|--------|
| `↓` / `↑` | Déplace la sélection dans la liste courante |
| `Entrée` | Active l'élément sélectionné (= clic sur le `<a>`) |
| `←` / `Retour arrière` | Remonte d'un niveau (hash du dossier parent) ; sans effet à la racine |
| `/` | Focus sur le champ de recherche |
| `Échap` | Vide la recherche, focus rendu à la liste |
| `t` | Bascule le thème clair/sombre |
| `c` | Classe suivante (équivalent du `<select>` classe) |

Garde-fous :
- les raccourcis **lettres** (`t`, `c`) et `/` sont **ignorés quand le focus est
  dans le champ de recherche** (pour pouvoir taper) ;
- `Entrée` et les flèches restent actifs depuis la recherche pour piloter la
  liste ;
- tout re-rendu de liste réinitialise `selection` à 0.

### Recherche améliorée

Dans `rechercher()` :

1. **Insensible aux accents.** Helper
   `normaliser(s) = s.toLowerCase().normalize("NFD").replace(/\p{Diacritic}/gu, "")`.
   La comparaison se fait sur `normaliser(nom)` vs `normaliser(q)`.
   « probleme » trouve « problème ».
2. **Chemin du résultat affiché.** Chaque résultat montre son **dossier parent**
   (dérivé du chemin déjà connu via `collecter()`), affiché en sous-titre
   discret (`.meta`). Répond au manque actuel : savoir *où* vit le fichier. Le
   clic continue de naviguer vers le fichier via `ligne`.

### Hors-scope (décidé)

Pas de surlignage de la correspondance, pas de recherche multi-classes, pas de
raccourcis vim-like.

## 5. Tests, docs, compatibilité

### Tests (hors-ligne, dans `tests/`)

- **`cdp_config.py`** : charger absent/vide/valide/version-future ; résolution
  cascade cwd→HOME (`tmp_path` + `monkeypatch` du HOME) ; override `--config` ;
  `ajouter_ou_maj` (insert + update) ; `selectionner` (ok + nom inconnu lève) ;
  `retirer` / `lister` ; écriture atomique (pas de `.part` résiduel).
- **Scraper** : rétrocompat `--url` (n'ouvre pas la config) ; parsing des
  nouveaux flags ; sélection des classes ; logique « classe absente → proposer
  mémorisation » isolée (sans réseau).
- **Viewer Q2** : `page_erreur` contient le code et le bon message contextuel,
  `Content-Type: text/html` ; le 500 d'API reste du JSON.
- **Viewer V6** : `normaliser()` (accents) testée comme fonction pure. Le DOM /
  clavier reste couvert par de la logique pure (pas de navigateur, cohérent avec
  l'existant).

### Docs

- `README.md` : section config (emplacement cascade, `--config`, format, rappel
  sécurité « jamais le mot de passe »), multi-classes (menu + noms en argument),
  nouveaux flags. Tableau d'arguments mis à jour.
- `CHANGELOG.md` : entrée `## [1.3.0]` (S3, S5, Q2, V6).
- Bump `1.2.0 → 1.3.0` dans `cdp_scraper.py`, `cdp_viewer.py`,
  `cdp_manifeste.py` (et l'assertion `--version` des tests).
- Aide CLI (`argparse`, epilog) actualisée.

### Compatibilité

- Aucune rupture : sans config et avec `--url`, comportement v1.2 identique.
- `.gitignore` couvre déjà `.cdp-scraper/` ; le HOME `~/.cdp-scraper/` n'est
  jamais dans le repo. Vérifier, rien à ajouter a priori.
- `cdp_manifeste.py` inchangé : le multi-classes appelle le pipeline existant en
  boucle, un manifeste par classe comme aujourd'hui.

## Critères de réussite

- Un run sans argument, config peuplée, propose un menu et traite les classes
  choisies ; `--tout` les traite toutes sans interaction.
- Une classe scrapée en interactif peut être mémorisée, puis relancée par son
  nom ; le mot de passe est toujours redemandé, jamais stocké.
- Les pages d'erreur du viewer sont thémées, contextuelles, avec retour accueil.
- Le viewer se pilote au clavier (flèches/Entrée/remontée + `/`, `Échap`, `t`,
  `c`) ; la recherche ignore les accents et montre le dossier de chaque résultat.
- Suite de tests hors-ligne verte sur la CI existante.

# Spec — v1.6 « Vérification et mise à jour »

> Établie le 2026-09-06. Sous-projet de la feuille de route
> (`docs/superpowers/specs/2026-06-21-roadmap.md`). Cycle *spec → plan →
> implémentation → revue*. Cible de version : **1.6.0**.

## Périmètre

Le projet publie maintenant de vraies releases GitHub taguées (v1.5.0 est la
première). Un utilisateur qui a téléchargé une version antérieure via
**ZIP** (pas de Git) n'a aujourd'hui aucun moyen de savoir qu'une nouvelle
version existe. Pire : télécharger et extraire un nouveau ZIP crée un
**nouveau dossier**, séparé de `cours_cdp/` (documents déjà téléchargés) et
`.cdp-scraper/` (config, coffre de mots de passe) qui restent dans
l'ancien — une simple notice ne suffit donc pas, il faut pouvoir mettre à
jour **sur place**, dans le dossier existant.

Objectif, en deux parties :

1. Le scraper et le viewer vérifient automatiquement, une fois par jour au
   plus, si une version plus récente est publiée sur GitHub.
2. Si oui, la notice **propose directement** de mettre à jour maintenant :
   - dossier Git → `git pull` (avec confirmation) ;
   - dossier ZIP (pas de `.git`) → télécharge et remplace **sur place** les
     fichiers du projet (jamais `cours_cdp/` ni `.cdp-scraper/`), tout ou
     rien.

Hors-scope : notification pour les versions préliminaires/pré-release,
exécutable `.exe` (v2.0, pas encore publié), relance automatique du process
après mise à jour (l'utilisateur relance la commande lui-même).

## Principes directeurs

- **Jamais bloquant au démarrage.** La vérification a un timeout court (2 s),
  toute erreur réseau est avalée silencieusement — le script continue
  normalement, hors-ligne ou non. La mise à jour elle-même (téléchargement
  des fichiers) n'a lieu que si l'utilisateur la demande explicitement.
- **Un seul appel réseau de vérification par jour, partagé.** Résultat mis en
  cache dans `.cdp-scraper/maj.json` ; scraper et viewer lisent/écrivent le
  même fichier (cascade cwd→HOME identique à `cdp_config`/`cdp_coffre`). Le
  cache est mis à jour **même en cas d'échec** (pour ne pas retenter l'appel
  à chaque run tant qu'on est hors-ligne).
- **Zéro dépendance ajoutée.** Nouveau module `cdp_maj.py` en stdlib pur
  (`urllib.request`, `json`, `subprocess`) — le viewer doit rester sans
  dépendance externe ; le scraper n'a donc pas besoin d'utiliser `requests`
  ici non plus (cohérence d'un seul module partagé).
- **La mise à jour ne touche jamais aux données utilisateur.** `cours_cdp/`
  et `.cdp-scraper/` ne font jamais partie des fichiers remplacés. Pour le
  cas ZIP, seuls les fichiers utiles à l'exécution sont concernés (`*.py`,
  `requirements*.txt`, `README.md`, `CHANGELOG.md`, `LICENSE`) — jamais
  `tests/`, `docs/`, `.github/`.
- **Tout ou rien.** Pour le remplacement de fichiers (cas ZIP), tous les
  fichiers sont téléchargés en mémoire et vérifiés avant qu'aucun ne soit
  écrit sur disque. Un seul échec de téléchargement annule toute
  l'opération : jamais d'installation à moitié mise à jour.
- **Liste de fichiers dynamique, pas figée dans le code.** La liste des
  fichiers à remplacer est lue depuis l'API GitHub (*Contents*) pour le tag
  ciblé, pas codée en dur : un futur nouveau module ajouté au dépôt sera pris
  en compte sans avoir à modifier une vieille version de l'outil.
- **Confirmation explicite avant toute écriture.** `git pull` et le
  remplacement de fichiers sont toujours précédés d'une question `[o/N]` qui
  précise noir sur blanc ce qui va être touché (et ce qui ne le sera pas).
  Jamais déclenché hors terminal interactif.
- **Désactivable et transparent.** Flags `--sans-verif-maj` (scraper,
  cohérent avec `--sans-colles`) et `--no-verif-maj` (viewer, cohérent avec
  `--no-browser`) désactivent toute la fonctionnalité (vérification incluse).
  La mention RGPD est mise à jour pour rester honnête (comme pour le coffre
  en v1.4).
- **Tests 100 % hors-ligne** : tout appel réseau (vérification, liste de
  fichiers, téléchargement, `git pull`) est isolé dans une fonction dédiée,
  mockée dans les tests.

## 1. Module `cdp_maj.py`

### Fichier de cache

`.cdp-scraper/maj.json`, même cascade que `cdp_config.chemin_config` /
`cdp_coffre.chemin_coffre` (pas d'override CLI dédié : ce cache n'est pas une
donnée que l'utilisateur a besoin de déplacer).

```json
{
  "derniere_verif": "2026-09-06T18:30:00",
  "derniere_version_connue": "1.5.0"
}
```

Pas de champ `version` de schéma ici (contrairement à `config.json`/`coffre.json`) :
c'est un cache jetable et non critique, pas une donnée utilisateur — un
format inattendu se régénère simplement au prochain essai, sans notion de
compatibilité à gérer.

- `derniere_verif` : horodatage du dernier **essai** (réussi ou non).
- `derniere_version_connue` : dernier tag obtenu avec succès (absent tant
  qu'aucun appel n'a réussi), **sans** le préfixe `v`.

### API — vérification

- `chemin_maj(override: str | None = None) -> Path` — cascade cwd→HOME,
  calquée sur `cdp_config.chemin_config`.
- `charger(chemin: Path) -> dict` — absent/illisible → `{}` (pas d'erreur
  fatale ; les clés manquantes sont lues via `.get()` avec des valeurs par
  défaut dans `verifier_maj`).
- `enregistrer(chemin: Path, donnees: dict) -> None` — écriture atomique
  (`.part` → renommage), comme les autres modules.
- `_version_tuple(s: str) -> tuple[int, ...]` — parse `"1.5.0"` ou `"v1.5.0"`
  en `(1, 5, 0)` ; renvoie `()` si le format est inattendu (comparaison
  toujours `False` dans ce cas, jamais d'exception).
- `derniere_version_github(depot: str, timeout: float = 2.0) -> str | None`
  — `GET https://api.github.com/repos/<depot>/releases/latest` (`depot` =
  `"Bastien-Gaffet/cdp-scraper"`), en-tête `User-Agent` requis par l'API
  GitHub. Renvoie `tag_name` sans le préfixe `v`, ou `None` pour **toute**
  erreur (réseau, timeout, JSON invalide, clé absente, code HTTP ≠ 200).
- `verifier_maj(version_locale: str, chemin_cache: Path, depot: str) -> str | None`
  — logique complète :
  1. Charge le cache.
  2. Si `derniere_verif` date de moins de 24 h → **pas d'appel réseau**,
     réutilise `derniere_version_connue` du cache.
  3. Sinon → appelle `derniere_version_github`. Écrit systématiquement
     `derniere_verif = maintenant` (succès ou échec) ; met à jour
     `derniere_version_connue` **seulement en cas de succès**.
  4. Si une version connue existe et que
     `_version_tuple(connue) > _version_tuple(version_locale)` → renvoie la
     version connue ; sinon `None`.

### API — mise à jour sur place

- `est_depot_git(dossier: Path) -> bool` — teste `(dossier / ".git").is_dir()`.
- `git_pull(dossier: Path) -> tuple[bool, str]` — lance
  `subprocess.run(["git", "pull"], cwd=dossier, capture_output=True, text=True, timeout=30)`.
  Renvoie `(succès, message)` (stdout+stderr concaténés) ; jamais
  d'exception (capture `subprocess.SubprocessError` — inclut
  `TimeoutExpired` — et `OSError`, ex. `git` absent du PATH →
  `(False, message d'erreur lisible)`). Git lui-même refuse proprement s'il y
  a un conflit avec des modifications locales — aucune logique de fusion à
  réimplémenter ici.
- `EXTENSIONS_MAJ = (".py",)` et `FICHIERS_MAJ = {"requirements.txt", "requirements-dev.txt", "README.md", "CHANGELOG.md", "LICENSE"}`
  — critère de sélection d'un fichier à mettre à jour (cas ZIP).
- `lister_fichiers_maj(depot: str, tag: str, timeout: float = 5.0) -> list[dict] | None`
  — `GET https://api.github.com/repos/<depot>/contents?ref=<tag>` (tag avec
  préfixe `v`, ex. `"v1.6.0"`). Filtre les entrées `type == "file"` dont le
  nom correspond à `EXTENSIONS_MAJ`/`FICHIERS_MAJ`. Renvoie une liste de
  `{"nom": str, "download_url": str}`, ou `None` en cas d'erreur (même
  politique que `derniere_version_github` : jamais d'exception).
- `telecharger_fichiers(fichiers: list[dict], timeout: float = 10.0) -> dict[str, bytes] | None`
  — télécharge chaque `download_url` en mémoire (`urllib.request`). Si **un
  seul** téléchargement échoue → renvoie `None` immédiatement (rien
  d'écrit nulle part, ce n'est qu'un dict en mémoire à ce stade). Sinon
  renvoie `{nom_fichier: contenu_bytes}`.
- `appliquer_maj(dossier: Path, fichiers: dict[str, bytes]) -> None` —
  écrit chaque fichier de `fichiers` dans `dossier / nom`, atomiquement
  (`.part` → renommage), comme `cdp_config.enregistrer`. Appelée uniquement
  après un `telecharger_fichiers` réussi (jamais d'écriture partielle).

## 2. Orchestration partagée : `proposer_maj(...)`

Fonction unique dans `cdp_maj.py`, appelée identiquement par le scraper et le
viewer (évite de dupliquer le flux d'interaction) :

```python
def proposer_maj(version_locale: str, chemin_cache: Path, depot: str,
                  dossier_projet: Path, tty) -> None:
    nouvelle = verifier_maj(version_locale, chemin_cache, depot)
    if not nouvelle:
        return
    print(f"Une nouvelle version est disponible : {nouvelle} "
          f"(vous avez {version_locale}).")
    if not tty():
        return
    if input("Mettre à jour maintenant ? [o/N] : ").strip().lower() not in ("o", "oui"):
        return

    if est_depot_git(dossier_projet):
        if input("Dépôt Git détecté. Lancer `git pull` ? [o/N] : ").strip().lower() not in ("o", "oui"):
            return
        ok, message = git_pull(dossier_projet)
        print(message)
        if ok:
            print("Relancez la commande pour utiliser la nouvelle version.")
        return

    tag = f"v{nouvelle}"
    print("Récupération de la liste des fichiers du projet…")
    fichiers = lister_fichiers_maj(depot, tag)
    if not fichiers:
        print("Échec : impossible de récupérer la liste des fichiers. Rien n'a été modifié.")
        return
    print(f"{len(fichiers)} fichier(s) à mettre à jour "
          "(cours_cdp/ et .cdp-scraper/ ne sont jamais touchés).")
    contenus = telecharger_fichiers(fichiers)
    if not contenus:
        print("Échec du téléchargement d'au moins un fichier. Rien n'a été modifié.")
        return
    appliquer_maj(dossier_projet, contenus)
    print(f"Mise à jour vers {nouvelle} terminée. Relancez la commande.")
```

`tty` est injecté (au lieu d'appeler `sys.stdin.isatty()` en dur) pour rester
testable sans terminal réel — le scraper et le viewer lui passent chacun
leur propre `_tty` déjà existant (scraper) ou nouvellement ajouté (viewer,
copié de `cdp_scraper._tty`).

## 6. Tests

`tests/test_cdp_maj.py` (nouveau, hors-ligne, aucun appel réseau réel) :

**Vérification** (comme prévu initialement) :
- `_version_tuple` : cas normal, préfixe `v`, format inattendu → `()`.
- `charger`/`enregistrer` : absent → cache vide, round-trip, écriture
  atomique (pas de `.part` résiduel).
- `verifier_maj` : cache absent → appelle `derniere_version_github` (mocké),
  écrit le cache, renvoie la nouvelle version si supérieure ; version
  distante == ou < version locale → `None` ; cache < 24 h → n'appelle
  **pas** `derniere_version_github` ; cache > 24 h → rappelle ; échec réseau
  → `derniere_verif` mis à jour quand même, `derniere_version_connue`
  inchangée, jamais d'exception.
- `derniere_version_github` : mock de `urllib.request.urlopen` — succès,
  timeout, JSON invalide, code HTTP erreur → toujours `None` sauf succès.

**Mise à jour** :
- `est_depot_git` : `True` avec un dossier `.git` présent (créé dans un
  `tempfile.TemporaryDirectory`), `False` sinon.
- `git_pull` : mock de `subprocess.run` — succès → `(True, ...)` ; code
  retour non nul → `(False, ...)` ; `OSError` (git absent du PATH) →
  `(False, ...)`, jamais d'exception qui remonte.
- `lister_fichiers_maj` : mock de `urllib.request.urlopen` renvoyant un JSON
  de contenu de dépôt avec des fichiers `.py`, un `tests/` (`type: "dir"`),
  un `.github` (dossier), un `image.png` → seuls les fichiers pertinents
  sont retenus ; erreur réseau/JSON → `None`.
- `telecharger_fichiers` : tous les téléchargements réussissent → dict
  complet ; un seul échoue → `None` (rien de partiel).
- `appliquer_maj` : écrit bien chaque fichier dans le dossier cible,
  atomiquement (pas de `.part` résiduel), n'écrit **jamais** dans un chemin
  en dehors de `dossier` (pas de traversée de chemin sur un nom de fichier
  malicieux — filtrage déjà fait en amont par la liste blanche
  `EXTENSIONS_MAJ`/`FICHIERS_MAJ`, mais `appliquer_maj` elle-même rejette
  tout nom contenant un séparateur de chemin, défense en profondeur).
- `proposer_maj` (orchestration) : version à jour → aucune question posée ;
  hors tty → notice affichée, aucune question ; refus utilisateur (`n`) à
  n'importe quelle étape → aucun appel à `git_pull`/`telecharger_fichiers`/
  `appliquer_maj` ; dépôt Git + confirmation → appelle `git_pull`, pas
  `lister_fichiers_maj` ; dépôt ZIP + confirmation → appelle
  `lister_fichiers_maj`/`telecharger_fichiers`/`appliquer_maj` dans l'ordre ;
  échec à n'importe quelle étape → message d'échec clair, pas d'étape
  suivante appelée.

`tests/test_cdp_scraper.py` / `tests/test_cdp_viewer.py` (ajouts) :

- `--sans-verif-maj` / `--no-verif-maj` : quand présent, `cdp_maj.proposer_maj`
  n'est **pas appelé** (mock + `assert_not_called`).
- Sans le flag, `cdp_maj.proposer_maj` est appelé avec les bons arguments
  (version locale, chemin de cache, dépôt, dossier du projet, `_tty`).

## Compatibilité

- Comportement par défaut **changé** (nouveauté assumée) : un appel réseau
  vers GitHub a désormais lieu au plus une fois par jour, sauf désactivation
  explicite. Documenté dans l'avertissement et le README.
- `.gitignore` couvre déjà `.cdp-scraper/` : `maj.json` n'est jamais suivi
  par git.
- Aucun changement de schéma pour `config.json`/`coffre.json`.
- Le viewer reste sans dépendance tierce (aucun `pip install` supplémentaire
  déclenché par cette fonctionnalité, contrairement au coffre).
- La mise à jour sur place ne modifie jamais `cours_cdp/` ni `.cdp-scraper/`,
  quel que soit le mode d'installation.

## Critères de réussite

- Une version obsolète affiche la notice avec le bon numéro, au scraper
  comme au viewer, et propose de mettre à jour.
- Une installation à jour n'affiche rien.
- Hors-ligne, aucun ralentissement perceptible au-delà du premier essai de
  la journée (timeout 2 s max), et aucune erreur visible.
- `--sans-verif-maj` / `--no-verif-maj` supprime tout appel réseau pour ce
  run (vérification et mise à jour).
- Sur un dépôt Git, confirmer la mise à jour lance `git pull` et rien
  d'autre.
- Sur une installation ZIP, confirmer la mise à jour remplace les fichiers
  du projet sans toucher `cours_cdp/` ni `.cdp-scraper/`, ou n'écrit
  strictement rien en cas d'échec réseau à n'importe quelle étape.
- Suite de tests hors-ligne verte, aucun appel réseau ni sous-processus réel
  dans les tests.
